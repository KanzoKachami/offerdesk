# Offerdesk

CRM для запросов менеджеров и офферов рекламодателей.
Стек: Next.js 15 (App Router) · TypeScript · Tailwind 4 · Supabase · Vercel.

## Структура

- **Рекламодатель** → его **офферы**.
- **Оффер** = продукт (SANKRA): список гео, где он работает, и список сорсов, которые принимает
  (пусто — любой сорс). Плюс модель, ставка, капа, статус.
- **Запрос** от менеджера → **позиции** (одно гео = одна позиция) → к позиции подбираются офферы,
  у которых есть это гео и подходящий сорс.

## База (Supabase → SQL Editor)

**Обновить существующую базу:** запусти `supabase/update.sql` целиком — внутри 002…007 по порядку, данные не трогает, можно повторять.

**Пустая база (новый проект):** запусти `supabase/install.sql` (всё сразу), затем `supabase/seed.sql`.

По отдельности:

1. `supabase/schema.sql` — пересоздаёт всю базу с нуля (старые таблицы и данные удаляются).
2. `supabase/seed.sql` — 16 рекламодателей и офферы SANKRA, SLOTAZA. Нужен созданный пользователь
   (Authentication → Users → Add user, галочка Auto Confirm User).
3. `supabase/002_launches.sql` — запуски, запросы от реклов, язык рекла. Данные не трогает, можно запускать повторно.
5. `supabase/004_geos.sql` — недостающие гео (Африка, СНГ, Азия).
6. `supabase/005_auto_streams.sql` — поток создаётся при любом «одобрено»: ответ рекла по офферу, закрытие позиции с итогом, ответ менеджера в запросе от рекла; кнопка «→ В потоки» у позиции.
7. `supabase/006_currency.sql` — валюта ставки ($/€) в ответе рекла.
8. `supabase/007_streams_off.sql` — «Потоки» на паузе: автосоздание выключено, потоки очищены (готовый код — в `src/later`).

## Деплой

GitHub → Vercel (автодеплой). Переменные окружения в Vercel:
`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (Supabase → Project Settings → API).

## Что есть

- Запуски: после «рекл одобрил» карточка сама появляется на доске «Запуски»:
  ждём ссылку → ссылка получена → у интегратора → интегрировано → трафик пошёл → был деп
  (или «трафик не пошёл» / «остановлен»). Готовые тексты реклу, интегратору, менеджеру.
- Сообщение от рекла: пинг по начатому привязывается к запуску/позиции («рекл ждёт»),
  новый спрос становится запросом «от рекла» → спрашиваешь менеджеров → ответ реклу на его языке (RU/EN).

- Очередь: «Моё действие / Ждём рекла / Ждём менеджера», подсветка просрочки по SLA.
- Запросы: вставляешь сообщение менеджера → «Разобрать текст» → каждое гео становится позицией.
- Карточка запроса: подбор офферов, «Отправил / Пинганул / Ответ», готовые тексты реклу и менеджеру.
- Офферы и рекламодатели, менеджеры, адресаты, вебмастера, настройки SLA и справочников.

## Технические заметки

- `src/middleware.ts` — именно в `src/`, иначе вход не защищён.
- Ответы Supabase не кэшируются (`src/lib/supabase/server.ts`), иначе после действий показывались старые данные.
- В `src/app/(app)` нет `loading.tsx`: с ним Next.js иногда не применял обновлённую страницу после действия.
- Формы карточки запроса — `ActionForm` (свой submit + спиннер), а не встроенные form actions React.
- Регион функций Vercel должен совпадать с регионом Supabase (Vercel → Settings → Functions).
